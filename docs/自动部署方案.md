# 生产仓库自动部署方案

## 目标
当生产仓库（Repo C）有新的 push 时，自动将更新部署到线上服务器，无需手动操作。

---

## 方案一：GitHub Actions 自动部署（推荐）

### 原理
GitHub Actions 监听 `push` 事件 → 自动 SSH 到服务器 → 执行拉取代码 + 重新构建容器。

### 步骤

#### 1. 服务器端准备

```bash
# 登录服务器
ssh root@your-server-ip

# 克隆生产仓库到服务器
cd /opt
git clone https://github.com/your-username/your-repo.git listeen-web
cd listeen-web

# 创建 .env 文件（不要提交到 git）
cat > .env << EOF
SA_PASSWORD=YourStrong!Password@2024
JWT_KEY=your-super-secret-jwt-key
SERVER_IP=your-domain-or-ip
EOF

# 启动服务
docker-compose up -d --build
```

#### 2. 生成 SSH 部署密钥

```bash
# 在服务器上生成密钥对（用于 GitHub Actions 连接服务器）
ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/github_deploy_key -N ""

# 将公钥添加到 authorized_keys
cat ~/.ssh/github_deploy_key.pub >> ~/.ssh/authorized_keys

# 查看私钥（复制，后面要用）
cat ~/.ssh/github_deploy_key
```

#### 3. GitHub 仓库设置 Secrets

进入 GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret

添加以下 Secrets：

| Name | Value |
|---|---|
| `SERVER_IP` | 你的服务器 IP 或域名 |
| `SERVER_USER` | 服务器用户名（如 `root`） |
| `SSH_PRIVATE_KEY` | 上一步复制的私钥内容 |

#### 4. 创建 GitHub Actions 工作流

在项目根目录创建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to Production

on:
  push:
    branches: [ main ]  # 当 main 分支有 push 时触发

jobs:
  deploy:
    runs-on: ubuntu-latest
    
    steps:
    - name: Deploy to server
      uses: appleboy/ssh-action@master
      with:
        host: ${{ secrets.SERVER_IP }}
        username: ${{ secrets.SERVER_USER }}
        key: ${{ secrets.SSH_PRIVATE_KEY }}
        script: |
          # 进入项目目录
          cd /opt/listeen-web
          
          # 拉取最新代码
          git pull origin main
          
          # 重新构建并启动容器
          docker-compose up -d --build
          
          # 等待服务启动
          sleep 10
          
          # 检查服务状态
          docker-compose ps
          
          echo "✅ 部署完成！"
```

#### 5. 提交并推送

```bash
git add .github/workflows/deploy.yml
git commit -m "Add auto deploy workflow"
git push origin main
```

#### 6. 验证

- 每次 push 到 `main` 分支，GitHub Actions 会自动运行
- 在 GitHub 仓库 → Actions 页面查看部署进度
- 部署成功后，访问你的网站验证

## 方案二：Webhook 自动部署（轻量级）

### 原理
服务器上运行一个 Webhook 服务，监听 GitHub 的 Push 事件，触发部署脚本。

### 步骤

#### 1. 服务器上创建部署脚本

```bash
# 创建部署脚本
cat > /opt/deploy.sh << 'EOF'
#!/bin/bash
cd /opt/listeen-web
git pull origin main
docker-compose up -d --build
echo "Deployed at $(date)" >> /opt/deploy.log
EOF

chmod +x /opt/deploy.sh
```

#### 2. 安装 Webhook 服务

```bash
# 安装 webhook 工具
# Ubuntu/Debian:
sudo apt install webhook

# 或使用 Node.js 写一个简单的 webhook 服务
```

#### 3. 创建 Webhook 配置文件

```bash
cat > /opt/webhook.json << 'EOF'
[
  {
    "id": "deploy",
    "execute-command": "/opt/deploy.sh",
    "command-working-directory": "/opt/listeen-web"
  }
]
EOF
```

#### 4. 启动 Webhook 服务

```bash
webhook -hooks /opt/webhook.json -port 9000 -verbose &
```

#### 5. GitHub 仓库设置 Webhook

进入 GitHub 仓库 → Settings → Webhooks → Add webhook

| 设置项 | 值 |
|---|---|
| Payload URL | `http://your-server-ip:9000/hooks/deploy` |
| Content type | `application/json` |
| Events | Just the push event |
| Active | ✅ |

#### 6. 配置 Nginx 反向代理（可选）

```nginx
location /hooks/ {
    proxy_pass http://localhost:9000/hooks/;
}
```

## 方案三：轮询部署（最简单）

### 原理
服务器上运行一个定时任务，每隔一段时间拉取最新代码并部署。

### 步骤

#### 1. 创建部署脚本

```bash
cat > /opt/auto-deploy.sh << 'EOF'
#!/bin/bash
cd /opt/listeen-web

# 获取当前版本
BEFORE=$(git rev-parse HEAD)

# 拉取最新代码
git fetch origin main
git reset --hard origin/main

# 获取新版本
AFTER=$(git rev-parse HEAD)

# 如果有更新，重新构建
if [ "$BEFORE" != "$AFTER" ]; then
    echo "New commit detected: $AFTER"
    docker-compose up -d --build
    echo "Deployed at $(date)" >> /opt/deploy.log
else
    echo "No new commits"
fi
EOF

chmod +x /opt/auto-deploy.sh
```

#### 2. 添加定时任务

```bash
# 编辑 crontab
crontab -e

# 添加以下行（每 5 分钟检查一次）
*/5 * * * * /opt/auto-deploy.sh >> /opt/deploy-cron.log 2>&1
```

## 对比

| 方案 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|
| GitHub Actions | 自动化程度高，无需服务器额外服务 | 需要配置 SSH 密钥 | 推荐，适合大多数场景 |
| Webhook | 实时触发，资源占用少 | 需要开放端口，配置较复杂 | 对实时性要求高 |
| 轮询部署 | 最简单，无需额外配置 | 有延迟，浪费资源 | 临时方案或简单场景 |

## 推荐配置（GitHub Actions）

### 完整 `.github/workflows/deploy.yml`

```yaml
name: Deploy to Production

on:
  push:
    branches: [ main ]
  # 允许手动触发
  workflow_dispatch:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3
    
    - name: Setup .NET
      uses: actions/setup-dotnet@v3
      with:
        dotnet-version: '8.0.x'
    
    - name: Restore dependencies
      run: dotnet restore
    
    - name: Build
      run: dotnet build --no-restore
    
    - name: Test
      run: dotnet test --no-build --verbosity normal

  deploy:
    needs: test  # 测试通过后才部署
    runs-on: ubuntu-latest
    
    steps:
    - name: Deploy to server
      uses: appleboy/ssh-action@master
      with:
        host: ${{ secrets.SERVER_IP }}
        username: ${{ secrets.SERVER_USER }}
        key: ${{ secrets.SSH_PRIVATE_KEY }}
        script: |
          cd /opt/listeen-web
          git pull origin main
          docker-compose up -d --build
          docker-compose ps
          echo "✅ Deployed at $(date)"
```

## 注意事项

1. **敏感信息**：不要将 `.env`、密钥、证书等提交到 git
2. **数据库迁移**：如果有新的 Migration，需要在部署脚本中添加：
   ```bash
   docker-compose exec -T listen-service dotnet ef database update
   ```
3. **回滚**：如果部署失败，可以快速回滚：
   ```bash
   cd /opt/listeen-web
   git reset --hard HEAD~1
   docker-compose up -d --build
   ```
4. **零停机部署**：可以使用蓝绿部署或滚动更新（需要 Docker Swarm 或 Kubernetes）
