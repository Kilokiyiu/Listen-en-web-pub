# IdentityService — 用户认证服务

[← 返回项目说明](1.1%20项目说明.md)

## 1. 职责

负责用户的注册、登录、角色管理和 JWT Token 签发，是整个平台的统一认证入口。其他服务通过验证 JWT 中的 Claims 进行鉴权，无需直接依赖此服务。

## 3. 领域模型

### User（用户）

继承自 ASP.NET Core Identity 的 `IdentityUser<Guid>`，扩展了软删除能力。

| 字段 | 类型 | 说明 |
|------|------|------|
| `Id` | `Guid` | 用户唯一标识 |
| `UserName` | `string` | 用户名 |
| `Email` | `string` | 邮箱（也可作为登录凭据） |
| `CreationTime` | `DateTime` | 创建时间 |
| `IsDeleted` | `bool` | 软删除标记 |
| `DeletionTime` | `DateTime?` | 软删除时间 |

### Role（角色）

继承自 `IdentityRole<Guid>`，目前系统内置两个角色：

- `User` — 普通用户，可访问学习功能
- `Admin` — 管理员，可访问后台管理接口

## 4. API 接口

路由前缀：`/api/identity/Login`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| `POST` | `/Register` | 无 | 用户名 + 邮箱 + 密码注册 |
| `POST` | `/LoginByEmailAndPwd` | 无 | 邮箱 + 密码登录，返回 JWT |
| `POST` | `/LoginByUserNameAndPwdAsync` | 无 | 用户名 + 密码登录，返回 JWT |
| `GET` | `/GetUserInfo` | 需要 JWT | 获取当前用户信息 |
| `POST` | `/ChangePwdAsync` | 需要 JWT | 修改密码 |
| `POST` | `/CreateWorld` | 无 | **首次部署初始化**，创建默认管理员账号 |

> **注意**：`CreateWorld` 接口在已初始化后会返回 `409 Conflict`，不会重复执行。

### 登录响应示例

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "userName": "admin"
}
```

## 5. JWT 设计

Token Payload 中包含以下 Claims：

| Claim | 内容 |
|-------|------|
| `ClaimTypes.NameIdentifier` | 用户 `Id`（Guid） |
| `ClaimTypes.Role` | 用户所有角色（可多个） |

其他服务通过解析 JWT 获取 `UserId` 和 `Role`，无需查询 IdentityService。

## 6. 首次部署说明

部署完成后，执行以下请求初始化管理员账号：

```http
POST https://your-domain/api/identity/Login/CreateWorld
```

初始账号信息（记得及时修改密码）：

- 用户名：`admin`
- 角色：`User` + `Admin`
